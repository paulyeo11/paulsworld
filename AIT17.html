AIT17: My Friend Shared His GitHub Repo —
Why It Still Didn't Show Up AIT17：朋友把他的GitHub仓库分享给我——
为什么它还是没出现

✍️ Paul Yeo 📅 5 August 20262026年8月5日 ⏱️ 5 min read5分钟阅读
✅ Link copied!链接已复制！

My friend Yudi tried to share his GitHub repository with me. I got the email invite and clicked "Accept." Job done — or so I thought. But when I went to look for his repo on my Claude Code screen, it just wasn't there. Nothing showed up. Here's what I learned about why "accepting an invite" and "seeing the repo in your tool" are actually two completely separate steps. 我的朋友Yudi想把他的GitHub仓库分享给我。我收到了邮件邀请，点了"Accept"（接受）。我以为这样就搞定了。可是当我到Claude Code屏幕上去找他的仓库时，却怎么也找不到，什么都没有出现。以下是我学到的：原来"接受邀请"和"在你的工具里看到这个仓库"其实是完全不同的两个步骤。

The Problem — Invite Accepted, Repo Still Missing 问题所在——邀请已接受，仓库却还是不见

This is a really common mix-up, so I want to walk through it plainly. GitHub actually has two separate systems stacked on top of each other: 这其实是个很常见的混淆点，我想把它讲清楚。GitHub其实有两套完全独立的系统叠在一起：

🧩 Two Layers, Not One🧩 两层，不是一层
  • Layer 1 — GitHub.com itself: "Am I a collaborator on this repo?" This is what the email invite controls.第一层——GitHub.com本身："我是不是这个仓库的协作者？"邮件邀请控制的就是这一层。
  • Layer 2 — Your tool's connection to GitHub (Claude Code, VS Code, GitHub Desktop, a Slack integration, etc.): "Which repos has this specific app/tool been given permission to see?" This is a separate permission, on top of Layer 1.第二层——你所用工具与GitHub的连接（Claude Code、VS Code、GitHub Desktop、Slack集成等）："这个具体的应用/工具被允许看到哪些仓库？"这是叠加在第一层之上的另一个独立权限。

Accepting Yudi's invite only unlocked Layer 1 — you becoming a real collaborator on GitHub.com. It did nothing to Layer 2, which is what decides what shows up on your Claude Code screen.接受Yudi的邀请只解锁了第一层——让你在GitHub.com上真正成为协作者。它对第二层完全没有影响，而第二层才是决定你Claude Code屏幕上会显示什么的关键。

Step 1 — Confirm the Invite Actually Went Through 第一步——先确认邀请真的生效了

Check github.com directly直接去github.com检查

Open a browser, go to Yudi's repo URL (e.g. github.com/yudi/his-repo-name), and make sure you're logged into the same GitHub account the invite email was sent to. If the repo loads without a "404 — this is a private repository" error, you're genuinely a collaborator.打开浏览器，进入Yudi仓库的网址（例如 github.com/yudi/his-repo-name），并确认你登录的是收到邀请邮件的那个GitHub账号。如果仓库能正常打开、没有出现"404——这是一个私有仓库"的错误，说明你确实已经是协作者了。

Watch out for multiple GitHub accounts留意是不是有多个GitHub账号

A very common trap: you clicked "Accept" while logged into a different GitHub account than the one your coding tool actually uses. If you have more than one GitHub account (a work one, a personal one), double-check which one received and accepted the invite.一个非常常见的坑：你点"Accept"接受邀请时登录的GitHub账号，和你的编程工具实际使用的账号并不是同一个。如果你有不止一个GitHub账号（比如一个工作账号、一个个人账号），要仔细核对一下到底是哪个账号收到并接受了这个邀请。

Check for organization SSO检查是不是有组织单点登录（SSO）

If Yudi's repo lives under a company or organization account (not his personal one), some organizations require a separate "Authorize" step for Single Sign-On (SAML SSO) even after you've accepted the collaborator invite. Look for a banner on the repo page or in your GitHub notification settings that says something like "Authorize [Org Name]."如果Yudi的仓库是挂在公司或组织账号下面（不是他的个人账号），有些组织即使在你接受了协作者邀请之后，仍然需要另外做一次"单点登录（SAML SSO）授权"。留意仓库页面或GitHub通知设置里有没有出现类似"Authorize [组织名称]"的提示条。

Step 2 — Give Your Tool Permission to See the New Repo 第二步——授权你的工具能看到这个新仓库

This is the step people miss. Being a collaborator on GitHub.com does not automatically flow through to every app connected to your GitHub account — each app keeps its own list of which repos it's allowed to touch. 这一步是大家最容易漏掉的。在GitHub.com上是协作者，并不会自动同步到每一个连接到你GitHub账号的应用上——每个应用都有自己单独的一份"它被允许访问哪些仓库"的清单。

⚠️

For Claude Code / Claude in Slack specifically: the GitHub connection is powered by a GitHub App installation, and that installation was likely set up to only access a specific list of repos (either "All repositories" or "Only select repositories"). A brand-new repo you were just added to won't appear until that installation's repo list is updated.专门针对Claude Code / Slack中的Claude：它与GitHub的连接是通过安装一个GitHub App来实现的，这个安装当初很可能被设置为只能访问一份特定的仓库清单（要么是"所有仓库"，要么是"仅选定的仓库"）。一个你刚被加进去的新仓库，在这份清单更新之前是不会出现的。

Find the GitHub App's settings找到GitHub App的设置

Go to github.com → your profile photo (top right) → Settings → Applications → Installed GitHub Apps (or, if Yudi's repo is under an organization: go to that organization's Settings → Third-party Access instead). Look for the Claude / Claude Code / Claude in Slack app in the list.前往 github.com → 右上角头像 → Settings（设置）→ Applications（应用）→ Installed GitHub Apps（已安装的GitHub App）（如果Yudi的仓库是在某个组织下面，那就改成去那个组织的 Settings → Third-party Access）。在列表里找到Claude / Claude Code / Slack中的Claude这个应用。

Add the repo to its access list把仓库加进它的访问清单

Click "Configure" next to the app. If it's set to "Only select repositories," you'll see an "Add repositories" dropdown — find and add Yudi's repo there, then Save. If it's already set to "All repositories," this step isn't the issue and you can skip to the next section.点击该应用旁边的"Configure"（配置）。如果设置的是"Only select repositories"（仅选定的仓库），你会看到一个"Add repositories"（添加仓库）的下拉菜单——在那里找到并添加Yudi的仓库，然后保存。如果原本设置的就是"All repositories"（所有仓库），说明这一步不是问题所在，可以跳到下一部分。

Re-check inside your tool回到工具里重新检查

Back in Claude Code (or whichever tool you're using), refresh or re-open the repo picker / source list. The repo should now show up. If your tool has a specific "Add repository" action, use that — it's designed exactly for this moment.回到Claude Code（或你正在使用的其他工具）里，刷新或重新打开仓库选择器/来源列表。这时候仓库应该就会出现了。如果你的工具有专门的"添加仓库"功能，用那个功能——它就是为这种情况设计的。

Step 3 — If You're Using Git/VS Code Locally Instead 第三步——如果你用的是本地的Git/VS Code

If "code screen" means a local code editor rather than a cloud tool, the fix is different: being a collaborator doesn't make the repo magically appear on your computer. You still need to actually clone it. 如果所说的"代码屏幕"指的是本地的代码编辑器，而不是云端工具，那解决方法就不一样了：成为协作者并不会让仓库自动出现在你的电脑上。你仍然需要真正地把它克隆（clone）下来。

💻 Quick Local Fix💻 快速本地修复
  • Go to Yudi's repo page on github.com and copy the URL from the green "Code" button.在github.com上打开Yudi的仓库页面，从绿色的"Code"按钮里复制网址。
  • Run git clone [that URL] in a terminal, or use "Clone Repository" in VS Code / GitHub Desktop and paste the URL.在终端里运行 git clone [那个网址]，或者在VS Code / GitHub Desktop里用"Clone Repository"（克隆仓库）功能，粘贴那个网址。
  • If it asks you to log in, make sure it's the same account that accepted the invite.如果要求你登录，确保用的是接受邀请的那个账号。

What I Learned 我学到了什么

💡

The lesson: "Accept invite" only makes you a collaborator on GitHub itself. Every tool that talks to GitHub — Claude Code, VS Code, GitHub Desktop — has to be separately told which repos it's allowed to see, or told to clone a fresh copy. If a shared repo doesn't appear, the invite almost certainly isn't the broken part — the missing second step is. 经验教训："接受邀请"只会让你成为GitHub本身的协作者。每一个与GitHub对接的工具——Claude Code、VS Code、GitHub Desktop——都需要另外被告知它可以看到哪些仓库，或者被告知去克隆一份新的。如果分享的仓库没有出现，问题几乎肯定不在邀请本身，而是缺了后面这一步。
